## 방법론에서 얻은 교훈

작업하다 여러 번 틀렸고, 그 경위가 다음 판단에 중요합니다.

**1. 단일 분할은 믿을 수 없습니다 (02 → 03)**
개선폭(2~14%)보다 폴드 간 편차(표준편차 7~38)가 큽니다. 한 번만 재면 과대평가도
과소평가도 납니다. 감자는 2026H1에서 -7.3%였는데 2024H2에서 +21.8%였습니다.

**2. 지표를 잘못 고르면 판정이 뒤집힙니다 (03 → 04)**
"개선 비율의 평균"으로 재면 오차 수준이 낮은 품목이 과대 반영됩니다. 생강은
naive MAPE가 1.7~3이라 절대 오차 0.4 증가가 +23%로 증폭됐습니다.
**MAPE는 이미 백분율이니 절대값으로 비교하세요.**

**3. 노이즈 플로어는 난수 피처로 재세요 (07 → 08)**
07번에서 "미나리가 100% 결측인데 -0.194 움직였으니 ±0.2가 노이즈"라고 봤는데
**6배 과대평가**였습니다. 결측 없는 난수 피처 4개를 넣고 seed를 바꾸면
**표준편차 0.012, 최대폭 0.034** 입니다.
참고로 `random_state` 만 바꾸는 방식으로는 못 잽니다: `early_stopping=False` 에
`max_features` 기본값이면 완전 결정론적이라 표준편차가 정확히 0입니다.

**4. 척도를 바꾸면 보이는 게 달라집니다 (11 → 12)**
변화율로 재서 "안 되는 품목"이라 했던 양배추·무가, 방향으로 재면 찍기를
10%p 넘게 이깁니다. **무엇을 재고 있는지 의심하세요.**

**5. 판정에 미래를 쓰지 마세요 (04·11 공통)**
"결과를 보고 품목/시기를 고르면" 그게 룩어헤드입니다. 04·11번 모두 이전 폴드
결과만 누적해서 썼고, 그 정직한 설정 덕분에 "규칙이 실패했다"는 결론이 나왔습니다.

**6. 기권이 선택지에 있으면 분기가 통합니다 (04·11 → 15)**
04번은 "이 품목엔 모델, 저 품목엔 naive", 11번은 "이 시기엔 모델"처럼 **무엇을
쓸지**를 갈랐고 둘 다 실패했습니다. 15번은 **언제 행동할지**를 갈랐고 성공했습니다.
앞의 둘은 어느 쪽을 고르든 행동을 하지만, 15번은 애매하면 아무것도 안 합니다.
분기 규칙이 안 될 때는 "선택지에 기권이 있는가"를 의심하세요.

**7. 노이즈 플로어는 척도마다 다시 재세요 (08 → 16)**
08번에서 MAPE 기준 노이즈가 **±0.03** 이었습니다. 같은 방식으로 16번에서 방향
적중률 기준을 재니 **±1.15%p** 입니다. 품목이 6개로 줄고 판정이 이진이라
훨씬 넓습니다. **08번 숫자를 그대로 가져다 쓰면 노이즈를 성과로 읽습니다.**
품목별로는 더 넓어집니다(1.26~2.76%p): 표본이 6분의 1이라서입니다.

### 1. 중간 지대 4품목 전용 모델 — 가장 실질적

상추·얼갈이배추·풋고추·배추만 골라 재면 **+4.41%** 로 실행 가능 전체(+2.07%)의
두 배가 넘습니다. 확신하는 날만 고르면 넣은 물량 대비 **16.2%** 이고, 17번에서
품목당 연 51일(주 1회꼴)로 운영 가능한 것까지 확인됐습니다. 지금은 19품목을 한
모델로 학습하는데, **이 넷만 따로 학습하면 더 나올 수 있습니다.**

다만 16번에서 "학습 품목을 6 → 19개로 늘려도 기존 품목 성적은 안 오른다"가
나왔으니, 반대 방향(19 → 4)도 차이가 없을 가능성이 있습니다. **노이즈 플로어를
4품목 기준으로 다시 재야** 판정이 납니다(교훈 7).

### 2. 정체 품목 셋을 대상에서 뺄지 결정 — 17번이 남긴 것

**피마늘·깐마늘·생강은 출하 시점 결정에 쓸 수 없습니다.** 확신하는 날은 많은데
전부 "내린다" 쪽이라 창고행이 연 0.0~5.9일입니다. 구매 시점(H2) 용도로는
쓸 수 있는지 따로 봐야 합니다.

### 3. 출하량 실마리를 같은 커버리지로 다시 재기 — 16번이 남긴 것

16번에서 출하량은 전체 적중률에 값을 못 했는데, **확신하는 날만 보면 노이즈
밴드를 벗어났습니다**(기본 66.42% · 난수 밴드 66.40~68.37% · 출하량 69.56%).
다만 확신한 날 비율이 35.81% → 37.11% 로 같이 움직여 표본이 달라, 지금 비교는
성립하지 않습니다. 15번 5절 방식으로 커버리지를 맞춰 재야 판정이 납니다.
**여기서 확정되면 아래 6번이 되살아납니다.**

### 4. 보관비 실측치 확보

창고비 한도가 실행 가능 전체 4.80%, 중간지대는 7~9%, 중간지대 + 확신한 날만
고르면 **16.2%** 입니다. **7거래일 창고비가 그보다 작은지**가 전략의 성패를
가릅니다. 저온저장고 운영비 자료를 찾아야 합니다.

17번에서 빈도까지 나왔으니 이제 구체적으로 물을 수 있습니다: **품목당 연 51회 ×
7거래일** 보관이고, 여름(6~7월)이 5월의 4~5배라 **용량은 여름 기준**입니다.

### 5. 등급 하락·감모 반영

지금 계산에는 저장 중 품질 저하가 안 들어갔습니다. 둘 다 창고비 한도를 낮추는
방향이라 **현재 숫자는 낙관적인 상한**입니다. KAMIS에 등급별 가격이 있다면
반영할 수 있습니다.

### 6. 신규 13품목에 datago·기상 매핑 붙이기 — 보류

**16번에서 근거가 사라졌습니다.** 출하량·기상이 방향 예측에 값을 못 했으니,
같은 데이터를 13품목에 더 붙일 이유가 없습니다. 며칠 걸리는 작업이라
**3번이 확정되기 전에는 착수하지 마세요.**

되살아난다면 방법은 이렇습니다: datago 일일한도가 1만 회라 백필을 며칠에 나눠야
하고, 매핑 자체는 datago 응답이 코드-이름 쌍(`gds_lclsf_nm`, `gds_mclsf_nm`)을
주므로 어렵지 않습니다. 기상은 `ITEM_STATIONS` 에 주산지 지점을 사람이 정해야
합니다.
