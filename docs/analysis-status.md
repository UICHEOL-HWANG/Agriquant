## 30초 요약

농산물 도매가를 **7거래일 뒤** 예측하는 작업입니다. 결론은 이렇습니다.

- **변화율(몇 % 오를까)은 못 맞힙니다.** naive("안 변한다") 대비 개선이 미미합니다.
- **방향(오를까 내릴까)은 맞힙니다.** 적중률 62.8% (찍기 기준선 51.1%).
- **쓸 자리는 출하 시점 결정**입니다. "오른다면 미루고 내린다면 오늘 판다"로
  평균 판매단가 **+2.85%**, 저장 가능 품목만 추리면 **+2.07%**.
- **가장 유망한 건 중간 지대 4품목**(상추·얼갈이배추·풋고추·배추): **+4.41%**.
- **애매한 날을 빼면 더 맞힙니다.** 모델이 확신하는 날(전체의 32%)만 고르면
  적중률 **72.1%**, 중간지대는 창고에 넣은 물량 대비 **16.2%** 까지 여유가 납니다.
- **운영 지점은 확신도 0.20 입니다.** 중간지대 4품목 기준 품목당 **연 51일**
  (주 1회꼴) 창고행에 적중률 **77.8%**, 12개월 전부에서 나옵니다.
- **창고비도 등급 하락도 발목을 잡지 않습니다.** 창고비 한도 대비 여유가
  **5~30배**(29번), 등급 하락은 **70~86%까지** 견딥니다(28·29번).
- **남는 돈은 출하 전량 대비 약 3%** 입니다. 1,000만 원어치에 **31.6만 원**.
  **쓸 수는 있지만 큰돈은 아닙니다** — 진짜 제약은 창고비가 아니라 **물량 규모**입니다.

- **모델을 더 짜낼 것이 없습니다**(30번). 후보 9개(앙상블·보정·다른 계열·재학습
  주기)를 커버리지 맞춰 비교했고 **채택안을 이겼다고 할 만한 것이 없습니다.**
  확률은 이미 잘 보정돼 있어 손댈 필요가 없었습니다.
- **모델보다 시기가 중요합니다**(30번). 후보끼리는 1%p 안쪽인데 **폴드끼리는
  57.2~68.1% 로 11%p** 벌어집니다. 성적이 떨어져도 반년은 봐야 판단이 섭니다.
- **창고가 유한해도 한도는 안 깎입니다**(31번). 오히려 13.83% → **17.12%로
  오릅니다** — 칸이 적으면 확신도 높은 것만 넣게 되어서입니다. 대신 **버는
  절대액이 6분의 1**로 줍니다. **용량 제약은 전략을 깨는 게 아니라 작게 만듭니다.**
- **평균에 맞춰 창고를 지으면 절반밖에 못 법니다**(31번). 재고 요구량이

### 결론은 `model/` 패키지에 있습니다 (노트북에 복붙하지 마세요)

노트북은 **왜 그렇게 정했는지**의 기록이고, 실행되는 코드는 `model/` 입니다.

| 파일 | 무엇 |
|---|---|
| `model/config.py` | 확정 상수. **각 값에 근거 노트북 번호가 달려 있습니다** |
| `model/data.py` | 마트 로드 (BigQuery / 파케이 캐시) |
| `model/features.py` | 채택 피처 21개 |
| `model/metrics.py` | 지표 8개 + 커버리지 맞춤 비교 |
| `model/evaluate.py` | 워크포워드 + **재현 검사** |
| `model/predict.py` | 오늘 시점 신호 |
| `model/store.py` | 예측 적재 + 채점 뷰 + 모델 식별자 |
| `model/monitor.py` | 신선도·커버리지·정체 검사 |

```bash
uv run python -m model.evaluate --check   # 15·19번 수치를 재현하는지
uv run python -m model.monitor            # 데이터 상태 (실패 시 종료코드 1)
uv run python -m model.predict --save     # 오늘 신호 → model_prediction
```

**상수를 바꾸려면 근거 노트북을 먼저 읽고, 바꾼 뒤 `--check` 를 돌리세요.**
재현이 안 되는 상태에서 성능을 비교하면 이식 실수인지 모델 때문인지
영영 못 가립니다.

**`--check` 는 행 수를 같이 봅니다.** 마트가 매일 커지므로 숫자가 조금씩
움직이는데, `EXPECTED_ROWS`(23,945) 와 다르면 **'회귀'가 아니라 '판정 보류'**
로 찍습니다. 행 수가 같은데 숫자가 다를 때만 코드를 의심하면 됩니다.

**모델 레지스트리는 따로 없습니다.** pickle 대신
`sha256(파라미터 + 피처목록 + 학습마지막날 + 학습행수)[:12]` 를 예측 행마다
박습니다. 학습이 결정적이라 **같은 식별자면 같은 모델이 재현됩니다.**
반년마다 재학습하면 `train_end` 가 바뀌어 식별자가 저절로 갈리고, 성적이
버전별로 나뉘어 집계됩니다.

| KAMIS 가 **요청보다 넓게 응답** | 하루를 요청했는데 3개월(1,005행)이 옴. append 로 받아 중복 2,908행 | `pipelines._clip_to_range()` 로 요청 구간 밖을 버림 |
| 클라이언트에 **날짜 하드코딩** | `--source kamis` 가 날짜를 안 넘겨 2025-01-01~2026-01-01 이 쓰임. 최근 8개월은 못 받으면서 1년치 중복 | 기본값 제거(필수 인자), `run_all` 이 최근 7일을 넘김 |
| **수집 목록 ≠ 마트 품목** | `--replace-range` 가 날짜만 보고 지워서, 목록에 없는 피마늘의 8/4~8/7 이 증발 | `DEFAULT_VEGETABLES` 를 19품목으로 맞춤 |

**공통 교훈**: 원천이 무엇을 주든 **내가 요청한 범위만 적재한다.** 그리고
**수집 목록은 테이블에 있는 품목 전체와 같아야 한다.**

적재 후 확인법: `COUNT(*) / COUNT(DISTINCT ...)` 가 1.0 이어야 합니다.
2021~2026-03 전 구간이 1.0 이라, 이 원천에 동일 행이 정상적으로 두 번
오는 일은 없습니다.

## 방법론에서 얻은 교훈

작업하다 여러 번 틀렸고, 그 경위가 다음 판단에 중요합니다.

**1. 단일 분할은 믿을 수 없습니다 (02 → 03)**
개선폭(2~14%)보다 폴드 간 편차(표준편차 7~38)가 큽니다. 한 번만 재면 과대평가도
과소평가도 납니다. 감자는 2026H1에서 -7.3%였는데 2024H2에서 +21.8%였습니다.

**2. 지표를 잘못 고르면 판정이 뒤집힙니다 (03 → 04)**
"개선 비율의 평균"으로 재면 오차 수준이 낮은 품목이 과대 반영됩니다. 생강은
naive MAPE가 1.7~3이라 절대 오차 0.4 증가가 +23%로 증폭됐습니다.
**MAPE는 이미 백분율이니 절대값으로 비교하세요.**

**3. 노이즈 플로어는 난수 피처로 재세요 (07 → 08)**
07번에서 "미나리가 100% 결측인데 -0.194 움직였으니 ±0.2가 노이즈"라고 봤는데
**6배 과대평가**였습니다. 결측 없는 난수 피처 4개를 넣고 seed를 바꾸면
**표준편차 0.012, 최대폭 0.034** 입니다.
참고로 `random_state` 만 바꾸는 방식으로는 못 잽니다: `early_stopping=False` 에
`max_features` 기본값이면 완전 결정론적이라 표준편차가 정확히 0입니다.

**4. 척도를 바꾸면 보이는 게 달라집니다 (11 → 12)**
변화율로 재서 "안 되는 품목"이라 했던 양배추·무가, 방향으로 재면 찍기를
10%p 넘게 이깁니다. **무엇을 재고 있는지 의심하세요.**

**5. 판정에 미래를 쓰지 마세요 (04·11 공통)**
"결과를 보고 품목/시기를 고르면" 그게 룩어헤드입니다. 04·11번 모두 이전 폴드
결과만 누적해서 썼고, 그 정직한 설정 덕분에 "규칙이 실패했다"는 결론이 나왔습니다.

**6. 기권이 선택지에 있으면 분기가 통합니다 (04·11 → 15)**
04번은 "이 품목엔 모델, 저 품목엔 naive", 11번은 "이 시기엔 모델"처럼 **무엇을
쓸지**를 갈랐고 둘 다 실패했습니다. 15번은 **언제 행동할지**를 갈랐고 성공했습니다.
앞의 둘은 어느 쪽을 고르든 행동을 하지만, 15번은 애매하면 아무것도 안 합니다.
분기 규칙이 안 될 때는 "선택지에 기권이 있는가"를 의심하세요.

**7. 노이즈 플로어는 척도마다 다시 재세요 (08 → 16)**
08번에서 MAPE 기준 노이즈가 **±0.03** 이었습니다. 같은 방식으로 16번에서 방향
적중률 기준을 재니 **±1.15%p** 입니다. 품목이 6개로 줄고 판정이 이진이라
훨씬 넓습니다. **08번 숫자를 그대로 가져다 쓰면 노이즈를 성과로 읽습니다.**
품목별로는 더 넓어집니다(1.26~2.76%p): 표본이 6분의 1이라서입니다.
**학습셋 크기도 폭을 바꿉니다**: 18번은 19품목 23,945행으로 학습해 ±0.57%p 로
좁았습니다. 난수 피처가 큰 학습셋 안에서 덜 흔들기 때문입니다.

**8. 묶으면 보이고 쪼개면 안 보입니다 (21·26 → 27)**
품목을 6개 묶어 재면 출하량 효과가 노이즈를 넘습니다(21번 +2.97%p, 26번 단기군
+1.87%p, 6/6 구간). 그런데 품목 하나로 쪼개면 폴드 간 표준편차가 평균보다 커져
아무것도 확정이 안 됩니다(27번: 미나리 3/7, 파 5/7, 대조군 배추도 표준편차 6.34).

**모순이 아니라 표본 문제입니다.** 묶으면 표본이 6배가 되어 노이즈가 좁아집니다.
품목당 관측일이 871일(폴드당 124일, 커버리지 40% 적용 시 50일 안팎)이라 품목
단위 판정에는 부족합니다. **그룹 결과를 품목에 귀속시키지 마세요.**

### 1. 보관비 — 29번에서 닫혔습니다 (실측치 없이)

**결론: 창고비는 병목이 아니었습니다.**

실측치는 끝내 못 구했습니다(아래 '찾아본 곳' 참조). 대신 **설치비에서
역산해 범위를 가뒀더니** 한도와 자릿수가 달랐습니다.

| | 창고비 한도 | 역산한 창고비 | 여유 |
|---|---|---|---|
| 중간지대 4품목 | 16.18% | 0.54 ~ 2.16% | **7 ~ 30배** |
| 실행 가능 11품목 | 13.25% | 0.71 ~ 2.86% | **5 ~ 19배** |

64개 조합(시공비 300~1,000만 · 전기료 50~400만 · 평당 300~2,000kg)을 전부
돌려도 **중간지대는 0/64**, 실행 가능 11품목은 4/64 만 한도를 넘습니다.
그 4개는 `전기료 연 400만` **그리고** `평당 300kg` 을 동시에 만족해야 합니다.

**"창고비를 못 구해서 판정할 수 없다"가 틀린 진단이었습니다.** 한도가 넉넉해서
정확한 값이 아니라 **자릿수만 맞으면** 결론이 납니다.

⚠️ **역산은 측정이 아닙니다.** 시공비는 2차 정보, 평당 저장량·전기료는 가정입니다.
주장은 "창고비는 X다"가 아니라 **"한도를 넘을 조합이 사실상 없다"** 입니다.
뒤집으려면 임차료가 물건값의 13% 를 넘거나, 회전이 연 36회보다 훨씬 낮아야 합니다.

**사는 쪽과의 교차점 1.31% 는 여전히 유효합니다.** 역산값(0.5~2.9%)이 이 선을
걸쳐서, **사는 쪽이 더 나을 가능성은 남아 있습니다.** 다만 20번에서 정한 대로
사는 쪽 숫자는 재고 제약을 뺀 상한이라 파는 쪽을 유지합니다.

### 2. 등급 하락 — 28번에서 닫혔습니다

경계선: `견딜 수 있는 하락확률 p = (한도 − 창고비 c) / 등급손실 g`

| 창고비 | 중간지대 4품목 | 실행 가능 11품목 |
|---|---|---|

| 2.16% | 77.1% | 62.4% |

**창고에 넣은 물건의 70~86% 가 등급이 떨어져도 남습니다.** 실무에서 7거래일

### 3. 신규 품목 출하량 매핑 — 고를 방법이 없습니다

**21 → 25 → 26 → 27번을 거치며 선별 기준이 전부 무너졌습니다.**

| 노트북 | 세운 기준 | 어떻게 됐나 |
|---|---|---|
| 21 | "출하량은 날 고르기에 값을 한다" | 그룹 수준에서는 유효 |
| 25 | "중간지대에도 될 것이다" | 반증(+0.22%p) |
| 26 | "저장성 있는 것부터" | **정반대**(상관 -0.723) |
| 27 | "파·미나리 같은 것" | **폴드로 쪼개면 무너짐** |

**남는 사실은 하나뿐입니다**: 출하량은 여러 품목을 **묶었을 때** 운영 지점에서
1~3%p 를 올립니다. **어느 품목에서 오는지는 이 데이터로 모릅니다**(교훈 8).

그래서 다음 품목을 **미리 고를 방법이 없습니다.** 붙여봐야 압니다. datago
일일한도가 1만 회라 며칠짜리 작업인데, 그걸 근거 없이 시작할지는 판단이
필요합니다. **하려면 저장성·품목 특성으로 고르지 말고 그냥 남은 품목을
전부 붙이는 게 낫습니다** — 어차피 선별 기준이 없습니다.

**31번에서 두 번째 동기가 생겼습니다.** 지금까지는 "피처로 값을 할지 모르니
붙여본다"뿐이었는데, 이제 **용량 시뮬레이션의 칸을 kg 으로 정규화**하는
용도가 추가됐습니다. 그게 되면 두 가지가 풀립니다.

- 창고 규모(칸)를 **평 단위 실물**로 환산할 수 있습니다
- **가격 높은 순 규칙**을 채택할지 판정할 수 있습니다(지금은 보류)

**피처로 값을 안 하더라도 이 용도만으로 값을 합니다.** 붙일 근거가
하나에서 둘이 됐습니다.

**기상은 제외합니다.** 16번에서 전 구간 악화였고 21번에서 다시 재지 않았습니다.

방법은 이렇습니다: datago 일일한도가 1만 회라 백필을 며칠에 나눠야
하고, 매핑 자체는 datago 응답이 코드-이름 쌍(`gds_lclsf_nm`, `gds_mclsf_nm`)을
주므로 어렵지 않습니다. 기상은 붙이지 않으므로 `ITEM_STATIONS` 작업은 필요 없습니다.
